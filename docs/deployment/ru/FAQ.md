# FAQ: 25 вопросов о моделях поставки

**Языки:** [Русский](FAQ.md) · [Deutsch](../de/FAQ.md) · [English](../en/FAQ.md)

## Что это и кому подходит

Этот FAQ отвечает на вопросы, которые возникают до выбора модели и в первые дни после
установки: где базовый URL, откуда взять токен, что делать при ошибке и куда уходят данные.
Он написан для владельца, администратора и первой линии поддержки, а не для разработчика
ядра. Ответы короткие, но каждый содержит команду или точный путь в интерфейсе, чтобы его
можно было проверить. Если нужна полная инструкция, в конце каждого ответа есть ссылка на
документ модели.

## Что понадобится

| Что | Требование | Проверка |
|---|---|---|
| Браузер | актуальный Chrome, Firefox, Edge или Safari | открыть кабинет |
| `curl` | 7.76+ | `curl --version` |
| Доступ | к кабинету или к серверу Runtime | вход в кабинет / SSH |
| Секрет | токен или `runtime.env` под рукой | не вставляйте в чат |
| Время | NTP, расхождение меньше 5 минут | `timedatectl status` |

Короткие ответы для клиента, продаж и первой линии поддержки. Если ответ начинается со
«зависит», рядом сказано, от чего именно. Все команды можно выполнить на машине, где
есть `curl`; секреты в примерах заменены плейсхолдерами.

### 1. Где базовый URL?

Их два типа, и они не взаимозаменяемы:

- **Copilot в облаке:** `https://burokratie.firmspace.de`; API — тот же хост плюс
  `/api/v1`, то есть `https://burokratie.firmspace.de/api/v1`.
- **Runtime on-prem:** адрес, который напечатал установщик строкой `API URL:`, например
  `http://192.168.1.20:8080`; API — `<этот адрес>/api/v1`.

Если терминал закрыт, адрес Runtime лежит в env-файле:

```bash
sudo grep '^BC_PUBLIC_BASE_URL=' /opt/firmspace-runtime/runtime.env
```

Проверка: `curl -fsS "$BASE_URL/actuator/health/readiness"` → `{"status":"UP"}`.

---

### 2. Где взять токен?

Токены три, и лежат они в разных местах:

| Токен | Где |
|---|---|
| Copilot API | Кабинет → Настройки аккаунта → API-токены → Создать токен |
| Мост | Кабинет роботов `https://agents.firmspace.de` → Предприятия → Подключения → Добавить мост → скачать `bridge.config.json` |
| Runtime admin | Генерирует установщик, лежит в `runtime.env`, переменная `BC_RUNTIME_ADMIN_TOKEN` |

`[СКРИНШОТ]` Карточка «API-токены» и диалог «Токен создан» — снять один раз и хранить во внутренней инструкции.

Пошагово с картинкой — в [README.md](README.md) §4 и
[схеме «Где взять токен»](../../images/token-locations.svg).

---

### 3. Что если токен потерян?

Восстановить нельзя: сервер хранит только SHA-256. Нужно отозвать старый и создать новый.

- Copilot: **API-токены** → найти по имени/`prefix` → **Отозвать** → **Создать токен**.
- Runtime: `POST /api/v1/runtime/tokens/<id>/revoke`, затем новый токен через
  `POST /api/v1/runtime/tokens`.
- Мост: в кабинете отозвать мост, создать новый, скачать новый
  `bridge.config.json`, импортировать, перезапустить контейнер.

После отзыва старый токен отвечает `401` на следующий же запрос.

---

### 4. Можно ли восстановить токен из базы?

Нет. В базе лежит только хеш. Поэтому «показать ещё раз» невозможно технически, а не
«забыли кнопку». Планируйте хранение в менеджере паролей сразу при создании.

---

### 5. Что если отозвали лицензию?

Владелец отзывает её в кабинете (**Лицензии → Отозвать**). Runtime примерно через минуту после старта и затем
каждые 6 часов спрашивает публичный статус по `LICENSE_CHECK_URL` и при `active:false`
переходит в `LICENSE_REVOKED`: агенты и workflow отвечают `402`, льготного периода нет.
Проверка работает, только если `LICENSE_CHECK_URL` передан в контейнер (в текущем
compose-файле это надо проверить командой `printenv LICENSE_CHECK_URL`). Без проверки
отзыв не доходит, пока ключ не заменят. Подробнее — [RUNTIME.md](RUNTIME.md) §5.5.

---

### 6. Работает ли без интернета?

- **Runtime:** да, для основной работы. Нужен только исходящий доступ, если клиент сам
  включил внешний AI, почту или обновления. Air-gap возможен, но обновления и поддержка
  требуют отдельного порядка.
- **Copilot SaaS:** нет. Это облачный сервис.
- **Мост:** работает с локальной очередью при недоступном кабинете, но задания и
  heartbeat требуют связи.

---

### 7. Куда уходят данные?

- **Только мост:** остаются у клиента; уходят только в настроенный приёмник.
- **Runtime:** остаются в контуре клиента; наружу — только если клиент включил внешний
  AI/почту/интеграцию.
- **Embedded API:** в инстанс, которому выдан токен (SaaS или Runtime клиента).
- **Copilot SaaS:** в облачный инстанс Firmspace, регион по договору (целевой ЕС).

Список субподрядчиков — [../compliance/subprocessors.md](../../compliance/subprocessors.md).

---

### 8. Как проверить, что документ попал в отчёт?

Три уровня проверки:

1. Ответ ingest: HTTP `201` и `documentId`.
2. Реестр документов: документ виден, есть категория и поля.
3. Отчёт: **Отчёты и аналитика** → **Расходы и привязка к ELSTER** → строка с этим
   `document_id`; в CSV колонка `document_id`.

Если документ есть, но строки в отчёте нет — проверьте год, категорию и дату. Документ без
категории/даты не скрывается, а появляется с предупреждением. Пустой год — `200` с нулями,
не ошибка.

### 10. Нужен ли свой сервер?

Нет для Copilot SaaS и Embedded API в облаке. Да для Runtime и для моста (машина/контейнер
у клиента). Минимум для Runtime: 4 vCPU, 8 ГБ RAM, 200 ГБ SSD; для моста — 512 МБ RAM и
2 ГБ диска.

### 12. Почему API отвечает 401?

`401 UNAUTHENTICATED` означает, что токен отсутствует, неизвестен, отозван или просрочен.
Проверьте:

```bash
curl -sS -o /dev/null -w '%{http_code}\n' \
  -H "Authorization: Bearer $TOKEN" \
  "$BASE_URL/api/v1/agents"
```

Если `401` — выпустите новый токен. Если `403` — токен валиден, но нет scope.

---

### 13. Почему API отвечает 402?

`402` — это лицензия/тариф, а не пароль:

- `LICENSE_MISSING` — в Runtime нет ключа;
- `LICENSE_READ_ONLY` — ключ истёк и grace закончился;
- `LICENSE_REVOKED` — лицензию отозвали в кабинете;
- `LICENSE_RUN_LIMIT` — исчерпан месячный лимит запусков;
- `SUBSCRIPTION_REQUIRED`/`PLAN_LIMIT_REACHED` — тариф SaaS.

Проверьте `curl -fsS "$BASE_URL/api/v1/license" | jq` и раздел
[RUNTIME.md](RUNTIME.md) §5.

---

### 14. Почему API отвечает 403?

Токен валиден, но у него нет нужного scope. Например, для ELSTER нужен `exports:read`, для
запуска — `agents.run`, для загрузки — `documents:write`. Права после создания не меняются:
выпустите новый токен с нужным набором.

---

### 15. Почему API отвечает 429?

Превышен лимит: по умолчанию 60 запросов в минуту на токен (120 для токена, выпущенного
Runtime-админом) или 600 в минуту на пользователя/IP. Сделайте backoff с jitter, не
повторяйте сразу. `Retry-After` может присутствовать не всегда.

---

### 16. Что такое scopes и какой минимум?

Scope — это право токена. Минимум зависит от задачи:

- загрузка файла — `documents:write`;
- чтение документов — `documents:read`;
- каталог/журналы — `agents.view`;
- запуск — `agents.run`;
- ELSTER — `exports:read`.

Не выдавайте `settings:write` сканеру или мосту. Один токен — одна задача.

---

### 17. Сколько токенов можно создать?

До **20 активных** на workspace. При попытке создать 21-й придёт ошибка/`409`; отзовите
ненужный. Для каждого тестового и продуктивного контура — отдельный токен.

---

### 18. Можно ли поставить Runtime и мост вместе?

Да, это две целые модели: Runtime на сервере клиента и мост на машине с legacy-софтом.
Данные остаются в контуре клиента. Это не «гибрид»: движок не делится между контуром и
облаком.

---

### 19. Можно ли поставить Copilot и мост вместе?

Да: Copilot в облаке и мост у клиента. Документы уходят в облако по настроенным каналам.
Мост при этом остаётся транспортом, а не движком.

---

### 20. Как обновляется каждая модель?

- **Copilot SaaS:** автоматически, клиенту делать нечего.
- **Runtime:** `git pull` → `docker compose build` → `up -d`; перед этим бэкап.
- **Мост:** загрузить новый образ, пересоздать контейнер с теми же томами, прогнать
  `bridge test`.
- **Embedded API:** обновляется вместе с инстансом, к которому подключён.

Подробно — [MANAGEMENT.md](MANAGEMENT.md) §6.

---

### 21. Где бэкапы?

- **Runtime:** PostgreSQL (`pg_dump -Fc`), каталог `runtime-data`, `runtime.env`. Команды —
  [MANAGEMENT.md](MANAGEMENT.md) §7.
- **Мост:** `config/bridge.config.json`, `config/.env`, том `.bridge`.
- **Copilot SaaS:** бэкапы делает Firmspace; клиент выгружает свои данные перед
  расторжением.
- **Embedded API:** ответственность владельца инстанса (SaaS или Runtime).

---

### 22. Как долго хранятся данные?

Зависит от модели и договора. В Copilot SaaS по умолчанию пробный период 60 дней и
хранение после окончания 100 дней; точные сроки — в договоре и настройках retention. В
Runtime срок задаётся настройками инстанса и договором; бэкапы хранятся по политике
клиента. Юридические документы — [../compliance/retention.md](../../compliance/retention.md).

---

### 23. Есть ли у Runtime веб-интерфейс?

Да. Откройте `http://<host>:8080/runtime-admin/`, вставьте `BC_RUNTIME_ADMIN_TOKEN` из
`runtime.env`, нажмите **Проверить**. На странице есть статус установки, установка лицензии,
первичная настройка предприятия и управление API-токенами. Страница не требует браузерной
сессии: каждый запрос несёт `X-Runtime-Admin-Token`, а сам токен хранится только в
`sessionStorage` вкладки. Подробные шаги — в [RUNTIME.md](RUNTIME.md) §6.

---

### 24. Можно ли посмотреть лицензию без токена?

Да. `GET /api/v1/license` открыт без авторизации: установщик, мониторинг и первый
оператор должны видеть состояние до появления токена. Ответ не содержит ключа, подписи
или секрета — только состояние, план, срок и `instanceId`.

```bash
curl -fsS "$BASE_URL/api/v1/license" | jq '{state, plan, expiresAt, daysRemaining}'
```

---

### 25. Что делать при инциденте и куда писать?

1. Зафиксировать время и симптом, снять логи, не перезапускать всё подряд.
2. Отозвать подозрительные токены, при утечке — сменить секреты.
3. Сообщить владельцу и в поддержку по контактам **из договора**.
4. Для утечки данных — действовать по [../compliance/breach-plan.md](../../compliance/breach-plan.md).

Контакты, часы и SLA в этой поставке не заданы: они фиксируются в договоре. Не
используйте вымышленные адреса поддержки.
