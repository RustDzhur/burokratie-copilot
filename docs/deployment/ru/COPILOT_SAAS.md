# Copilot как сервис (облако)

**Языки:** [Русский](COPILOT_SAAS.md) · [Deutsch](../de/COPILOT_SAAS.md) · [English](../en/COPILOT_SAAS.md)

**Модель:** готовый облачный кабинет Firmspace Copilot. Клиент не ставит серверы, не
обслуживает PostgreSQL и не обновляет контейнеры: он получает доступ по HTTPS,
настраивает каналы поступления документов и работает в браузере.

![Четыре модели поставки](../../images/deployment-models.svg)

*Схема 1. Copilot SaaS — четвёртая модель: данные и движок в облаке, у клиента только
браузер.*

---

## 1. Что это и кому подходит

Copilot как сервис — это аренда готового кабинета: документы, OCR, категории, задачи,
агенты, выгрузки и аудит уже работают, клиенту не нужен свой сервер. Всё управление идёт
через браузер по адресу `https://burokratie.firmspace.de`; для интеграций есть тот же
хост с префиксом `/api/v1`. Модель подходит малому и среднему бизнесу, налоговым бюро и
командам, которым нужен быстрый старт и которые допускают обработку данных в ЕС у
Firmspace. Если документы не могут покидать контур клиента — нужен
[Robots Runtime](RUNTIME.md).

## 2. Что понадобится

| Что | Требование | Как проверить |
|---|---|---|
| Браузер | актуальный Chrome, Firefox, Edge или Safari | открыть `https://burokratie.firmspace.de` |
| Интернет | исходящий HTTPS 443, без air-gap | `curl -I https://burokratie.firmspace.de` |
| Почта | доступ к ящику для подтверждения и приглашений | письмо от Firmspace |
| Пароль | 12–128 символов, не из списка частых | при регистрации |
| Время | NTP, расхождение меньше 5 минут | `timedatectl status` |
| `curl` | 7.76+, если будете проверять API | `curl --version` |

Саморегистрация может быть закрыта на конкретном инстансе. Если кнопка «Регистрация»
недоступна или возвращает ошибку, аккаунт создаёт администратор Firmspace — это
нормально для корпоративных поставок.

## 3. Базовый URL

| Что | Адрес |
|---|---|
| Кабинет | `https://burokratie.firmspace.de` |
| API | `https://burokratie.firmspace.de/api/v1` |
| Проверка здоровья | `https://burokratie.firmspace.de/actuator/health/readiness` |
| Статус лицензии инстанса | `https://burokratie.firmspace.de/api/v1/license` |

`BASE_URL` в примерах — это `https://burokratie.firmspace.de` **без** `/api/v1`; пути
добавляются в каждом запросе. Проверка:

```bash
export BASE_URL="https://burokratie.firmspace.de"
curl -fsS "$BASE_URL/actuator/health/readiness"
curl -fsS "$BASE_URL/api/v1/license" | jq '{state, plan}'
```

Если `curl` возвращает `404` на `/api/v1/license`, проверьте, что не добавили `/api/v1`
дважды и что прокси не режет путь.

## 4. Регистрация и первый вход

1. Откройте `https://burokratie.firmspace.de`.
2. Нажмите **Регистрация** (адрес `/register`).
3. Заполните: e-mail, пароль (12–128 символов), имя, тип аккаунта, название организации,
   язык и часовой пояс.
4. Подтвердите e-mail по ссылке из письма. Без подтверждения вход заблокирован.
5. Войдите (`/login`). При первом входе может открыться короткая настройка.

Типы аккаунта: частное лицо, семья, фрилансер/ИП, компания, команда, внешний
представитель, организация с повышенными требованиями. Тип влияет на кабинет и тариф, но
не меняет API.

`[СКРИНШОТ]` Экран регистрации и письмо подтверждения.

### 4.1 Роли

| Роль | Что может | Кому |
|---|---|---|
| `OWNER` | всё, включая передачу владения и удаление аккаунта | владелец |
| `ADMIN` | всё, кроме передачи владения/удаления | администратор |
| `MANAGER` | дела, задачи, документы, финансы, согласования | руководитель |
| `EMPLOYEE` | назначенные дела, документы, задачи | сотрудник |
| `ACCOUNTANT` | финансы, документы, выгрузки | бухгалтер |
| `LEGAL_ADVISOR` | договоры и юридические дела | юрист |
| `EXTERNAL_ADVISOR` | только назначенные дела | внешний консультант |
| `AUDITOR` | журналы и доказательства без изменений | аудит |
| `READ_ONLY` | просмотр | наблюдатель |

Права проверяются на сервере. Приглашённый получает доступ только после принятия
приглашения; один пользователь может состоять в нескольких организациях, но видит только
те, где у него есть членство.

## 5. Документы: как они попадают в кабинет

### 5.1 Каналы

| Канал | Где в интерфейсе | Когда |
|---|---|---|
| Загрузка вручную | **Сканирование и импорт** → перетащить файлы | разово |
| Реестр документов | **Реестр документов** → список и карточка | просмотр/поиск |
| Почта | **Почтовый центр** → подключить ящик | регулярно |
| Скан/МФУ | папка или мост | регулярно |
| API | `POST /api/v1/documents:ingest` | интеграция |
| Мост | кабинет роботов → подключение | если есть legacy |

### 5.2 Загрузка через браузер

1. Откройте **Сканирование и импорт** в левом меню.
2. Перетащите PDF/изображение в область загрузки или выберите файл.
3. Дождитесь статуса «Сохранено. Документ сейчас читается».
4. Откройте **Реестр документов**: документ появился в списке.
5. Если система не уверена в типе или полях, документ попадёт в **Центр проверки** —
   подтвердите или исправьте. Это нормальный сценарий, а не ошибка.

`[СКРИНШОТ]` Область загрузки и карточка документа со статусом обработки.

Ограничения по умолчанию: файл до 100 МБ, запрос до 250 МБ. Дубликаты определяются по
SHA-256: повторная загрузка того же файла не создаёт второй документ.

### 5.3 Что происходит дальше

1. Проверка типа, размера и сигнатуры; антивирус, если включён.
2. Извлечение текста: цифровой PDF читается напрямую, скан — через OCR.
3. Определение типа и полей; при низкой уверенности — проверка человеком.
4. Категория, папка, срок, задача; всё фиксируется в журнале.
5. Спорные документы — в **Центр проверки**, решение человека сохраняется.

Честно: OCR ошибается на плохих сканах, рукописи и нестандартных таблицах. Платформа
показывает уверенность и отправляет на проверку; «100 % автоматически» не обещается.
AI-функции могут быть выключены — тогда работают OCR и правила, но не AI-объяснения.

## 6. Где взять API-токен

Токен нужен, если внешняя система (ваш продукт, сканер, мост, скрипт) должна передавать
документы или запускать агентов.

1. Войдите в `https://burokratie.firmspace.de`.
2. Откройте меню аккаунта справа вверху → **Настройки аккаунта**.
3. Выберите карточку **API-токены**.
4. Нажмите **Создать токен**.
5. Введите **Имя** (например, `embedded-prod`).
6. Отметьте права:
   - **Передача документов** (`documents:write`) — для загрузки;
   - **Чтение документов** (`documents:read`) — если нужно читать;
   - **Просмотр агентов** (`agents.view`) — каталог и журналы;
   - **Запуск агентов** (`agents.run`) — запуск;
   - `exports:read` — для ELSTER-выгрузки (может отображаться техническим именем).
7. Нажмите **Создать токен**.
8. В диалоге **Токен создан** нажмите **Скопировать токен** и сохраните значение.

Значение показывается **один раз**. В списке видны имя, `prefix`, права, дата создания,
последнее использование и статус; самого токена там нет.

`[СКРИНШОТ]` Карточка «API-токены», диалог создания, диалог «Токен создан».

Если токен потерян: **API-токены** → найти по имени → **Отозвать** → создать новый.
Восстановление невозможно: сервер хранит только SHA-256.

Ограничения: максимум 20 активных токенов на workspace; 60 запросов в минуту по
умолчанию; права после создания не меняются; создавать может роль с
`api_tokens.manage`.

![Где взять токен](../../images/token-locations.svg)

*Схема 3. Три разных токена: Copilot API, мост, Runtime admin. Это не одно и то же.*

## 7. ELSTER-выгрузка

1. Откройте **Отчёты и аналитика**.
2. Найдите блок **Расходы и привязка к ELSTER**.
3. Введите год в поле года.
4. Нажмите **Выгрузить CSV** — файл `elster-<год>.csv` скачается в браузер.

Таблица на экране и CSV содержат одни и те же строки: экран и файл не могут рассказывать
разные истории. Документ без категории, строки или даты не скрывается — он появляется с
предупреждением.

`[СКРИНШОТ]` Блок «Расходы и привязка к ELSTER» с итогами и кнопкой выгрузки.

Формат CSV: разделитель `;`, десятичная запятая, фиксированный заголовок:

```text
category_code;euer_line;euer_kz;datev_skr03;datev_skr04;booking_kind;netto;ust;brutto;vorsteuer_abziehbar;bewirtung_abziehbar_70;bewirtung_nicht_abziehbar_30;document_id;date
```

Это не налоговая консультация: перед подачей бухгалтер проверяет правила и категории.
Подробнее — [../ELSTER_README.md](../../ELSTER_README.md).

## 8. Данные, хранение, тариф

### 8.1 Куда уходят данные

Документы, метаданные и журналы хранятся в облачном инстансе Firmspace. Регион — по
договору, целевой регион — ЕС. Наружу данные уходят только по включённым каналам:
почта, внешний AI-провайдер, интеграции. Список субподрядчиков и меры защиты —
[../compliance/README.md](../../compliance/README.md), [../compliance/subprocessors.md](../../compliance/subprocessors.md),
[../security.md](../../security.md).

### 8.2 Сроки

| Что | Значение по умолчанию | Где меняется |
|---|---|---|
| Пробный период | 60 дней | `billing.trial_days` |
| Хранение после окончания | 100 дней | `billing.retention_days` |
| Хранение документов в тарифе | по договору | тариф/настройки |

После окончания пробного периода доступ ограничивается; данные хранятся указанный срок,
затем удаляются, если не выбрано иное. Точные сроки для конкретного клиента фиксируются в
договоре, а не в этой таблице.

### 8.3 Тариф

Тарифы и цены — коммерческое решение, а не техническая константа. В поставке есть
стартовые значения в миграциях, но публичная оферта и SLA оформляются договором. Не
обещайте клиенту конкретную цену, пока она не зафиксирована.

## 9. Безопасность и ограничения

- TLS обязателен; не отключайте проверку сертификата.
- Пароль — 12–128 символов, не из списка частых.
- Вход можно защитить вторым фактором (MFA), если он включён в инстансе.
- Токены — только для серверных интеграций; в браузер и мобильное приложение их отдавать
  нельзя.
- Сессии истекают; после смены пароля старые сессии могут быть завершены.
- Экспорт и удаление данных — через процедуры платформы, не через SQL.
- Нет работы без интернета, air-gap, доступа к серверу/БД и «своего AI в один клик».
- Нет прямого API DATEV и юридической/налоговой консультации.

## 10. Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| Не приходит письмо подтверждения | спам, неверный адрес, закрытая регистрация | проверить спам; запросить письмо повторно; обратиться к администратору |
| Вход отклонён после регистрации | e-mail не подтверждён | подтвердить по ссылке |
| «Нет доступа» в API-токенах | нет права `api_tokens.manage` | попросить OWNER/ADMIN выдать роль |
| Не удаётся создать токен, «20 активных» | лимит workspace | отозвать ненужный токен |
| Загрузка файла не начинается | размер > 100 МБ или тип запрещён | уменьшить файл; проверить формат |
| Документ «читается» слишком долго | очередь OCR/нагрузка | подождать; проверить статус; обратиться в поддержку с `documentId` |
| Выгрузка ELSTER пустая | нет документов за год или нет категорий | проверить год и категории; пустой год — это `200`, не ошибка |
| API отвечает `401` | токен неверный/отозван | создать новый |
| API отвечает `403` | нет scope | выдать нужный scope новым токеном |
| API отвечает `402` | тариф/план | проверить тариф, обратиться к владельцу |
