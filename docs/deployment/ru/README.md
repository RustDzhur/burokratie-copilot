# Модели поставки: понятная инструкция

**Языки:** [Русский](README.md) · [Deutsch](../de/README.md) · [English](../en/README.md)

**Актуально на:** 28 октября 2026 года.
**Проверено по:** `scripts/install-runtime.sh`, `scripts/bootstrap-runtime.sh`,
`infra/docker-compose.runtime.yml`, `ApiTokenController`, `RuntimeAdminController`,
`ElsterExportController`, `ApiTokenAuthenticationFilter`, `LicenseService` и документации
Bridge (`firmspace-bridge`, версия 0.1.0).

Этот раздел объясняет **четыре способа поставить Firmspace / Bürokratie-Copilot** так,
чтобы было понятно без опыта: что вы получите, где это работает, откуда берётся базовый
адрес и где взять каждый токен. Здесь нет маркетинга: только то, что можно проверить
командой или увидеть в интерфейсе.

## 1. Что это и кому подходит

Firmspace можно поставить четырьмя разными способами, и они не взаимозаменяемы.
**Только мост** связывает старый софт клиента с платформой, но ничего не распознаёт.
**Robots Runtime** переносит движок агентов и документы на сервер клиента. **Embedded
API** даёт вашему продукту HTTP-доступ к распознаванию и агентам. **Copilot как сервис**
даёт готовый облачный кабинет без своей инфраструктуры. Выбор сводится к двум вопросам:
могут ли документы покидать контур клиента и кто будет обслуживать сервер. Ниже — карта,
которая помогает ответить на эти вопросы до установки, а не после.

## 2. Что понадобится

### 2.1 Минимум для любой модели

| Что | Требование | Как проверить |
|---|---|---|
| Браузер | актуальный Chrome, Firefox, Edge или Safari | открыть `https://burokratie.firmspace.de` |
| `curl` | 7.76 или новее | `curl --version` |
| Часы | синхронизация по NTP, расхождение меньше 5 минут | `timedatectl status` (Linux) |
| Канал | исходящий HTTPS 443; входящие порты не нужны | `curl -I https://burokratie.firmspace.de` |
| Место для секретов | менеджер паролей или файл с правами `600` | — |

### 2.2 Дополнительно для Runtime (on-prem)

| Что | Требование | Как проверить |
|---|---|---|
| ОС | Linux x86_64/arm64 (рекомендуется) | `uname -m` |
| Docker Engine | 24 или новее | `docker version --format '{{.Server.Version}}'` |
| Docker Compose | v2 | `docker compose version` |
| RAM | минимум 4 ГБ, рекомендуется 8 ГБ | `free -h` |
| Диск | минимум 10 ГБ свободно, рекомендуется 200 ГБ | `df -h` |
| `openssl` | любая актуальная версия | `openssl version` |
| `git` | нужен для исходников поставки | `git --version` |
| PostgreSQL | 17, входит в compose | `docker compose ... exec postgres psql --version` |

### 2.3 Дополнительно для моста

| Что | Требование | Как проверить |
|---|---|---|
| Docker Engine | 24 или новее | `docker version` |
| Архитектура | `amd64` или `arm64` | `uname -m` |
| RAM | 512 МБ + запас | `docker info` |
| Диск | 2 ГБ + место под очередь | `df -h` |
| Node.js | 22 LTS — **только** для варианта без Docker | `node -v` |
| Доступ к папкам | UID/GID 1000 внутри контейнера | `id -u` на хосте |

### 2.4 Дополнительно для Embedded API

| Что | Требование | Как проверить |
|---|---|---|
| TLS | валидный сертификат на домене API | `openssl s_client -connect <host>:443 -servername <host>` |
| `jq` | необязательно, но удобно для примеров | `jq --version` |
| Токен | выпущен с нужными `scopes` | `curl ... /api/v1/agents` |

> **Важно.** Во всех примерах ниже используются только плейсхолдеры `${BASE_URL}`,
> `${TOKEN}` и `<вставьте свой>`. Не подставляйте реальные токены в командную строку,
> историю shell, скриншоты и тикеты.

## 3. Как выбрать модель

### 3.1 Таблица выбора

| Ситуация клиента | Модель | Что ставится у клиента | Где работает движок | Куда уходят данные | Токен |
|---|---|---|---|---|---|
| Есть старый софт без API, нужен только обмен | [Только мост](BRIDGE_ONLY.md) | Firmspace Bridge | Нигде у клиента | Только в настроенный приёмник | Токен моста |
| Нужны OCR, агенты и журналы, документы не должны покидать контур | [Robots Runtime](RUNTIME.md) | API + PostgreSQL 17 | На сервере клиента | Не покидают контур | API-токен Runtime |
| Свой продукт должен вызывать распознавание и агентов | [Embedded API](EMBEDDED_API.md) | Только клиентский код | В SaaS или Runtime | В инстанс, которому выдан токен | Copilot или Runtime-токен |
| Нужен быстрый старт без инфраструктуры | [Copilot как сервис](COPILOT_SAAS.md) | Ничего, только браузер | У Firmspace | В облако Firmspace (ЕС) | Copilot API-токен |
| Нужны и агенты, и доступ к legacy | Runtime + мост | API + PostgreSQL + мост | На сервере клиента | Не покидают контур | Два токена, по одному на компонент |
| Нужны агенты в облаке и legacy на месте | Copilot + мост | Только мост | У Firmspace | В облако Firmspace | Два токена |

> **Гибрид не поставляется.** Нельзя разделить один движок между сервером клиента и
> облаком так, чтобы они делили одно хранилище и один tenant. Можно комбинировать **целые**
> модели: Runtime + мост, Copilot + мост.

### 3.2 Три вопроса вместо таблицы

1. **Документы могут покидать контур клиента?**
   - Нет → Runtime или Embedded API, развёрнутый в контуре клиента.
   - Да → Copilot как сервис.
2. **Кто пишет вызывающий код?**
   - Наш продукт или интегратор → Embedded API.
   - Никто, нужен готовый интерфейс → Copilot как сервис.
   - Нужен только обмен с legacy → только мост.
3. **Нужны ли OCR, категории и агенты?**
   - Нет → только мост.
   - Да → Runtime (on-prem) или Copilot (облако).

## 4. Три адреса, которые надо знать

Это первое, чего не хватало в прежней документации: **базовый URL** и **где взять
токен**. Запомните три адреса.

| Что | Адрес | Как проверить |
|---|---|---|
| Copilot в облаке | `https://burokratie.firmspace.de` | `curl -I https://burokratie.firmspace.de` |
| API Copilot в облаке | `https://burokratie.firmspace.de/api/v1` | `curl -fsS https://burokratie.firmspace.de/api/v1/license` |
| Кабинет роботов (мосты) | `https://agents.firmspace.de` | `curl -I https://agents.firmspace.de` |
| Runtime on-prem | адрес, который напечатал установщик, например `http://192.168.1.20:8080` | `curl -fsS http://192.168.1.20:8080/actuator/health/readiness` |
| API Runtime | `<адрес Runtime>/api/v1` | `curl -fsS http://192.168.1.20:8080/api/v1/license` |

Где посмотреть адрес Runtime, если терминал закрыт:

```bash
cd /path/to/burokratie-copilot
set -a; . infra/runtime.env; set +a
printf '%s\n' "$BC_PUBLIC_BASE_URL"
```

Если установка делалась с `--dir /opt/firmspace-runtime`, файл лежит по пути
`/opt/firmspace-runtime/runtime.env`. Внутри — `BC_PUBLIC_BASE_URL`; это и есть базовый
адрес. API всегда добавляет к нему `/api/v1`.

Токены — в трёх разных местах, и это не одно и то же:

| Токен | Где взять | Куда вставлять |
|---|---|---|
| Copilot API | Кабинет → Настройки аккаунта → API-токены → Создать токен | Заголовок `Authorization: Bearer ${TOKEN}` |
| Мост | Кабинет роботов → Предприятия → Подключения → Добавить мост | `bridge.config.json` и `.env` (`BRIDGE_TOKEN`) |
| Runtime admin | Установщик создаёт и кладёт в `infra/runtime.env` | Заголовок `X-Runtime-Admin-Token` |

Подробные шаги с картинками: [схема «Где взять токен»](../../images/token-locations.svg).

## 6. Как читать эти документы

- **Плейсхолдеры.** `${BASE_URL}` — адрес API без завершающего `/`. `${TOKEN}` — секрет,
  который вы получили в кабинете. `<вставьте свой>` — значение, которое нельзя придумать.
- **Пути.** Команды выполняются из корня поставки `burokratie-copilot`, если не указано
  иное. Пути внутри контейнера моста — это пути **контейнера**, а не хоста.
- **Ожидаемый результат.** После каждой команды написано, что должно появиться. Если
  появилось другое — это не «мелочь», а сигнал остановиться и проверить шаг.
- **Скриншоты.** Места, где нужен снимок живого интерфейса, помечены `[СКРИНШОТ]`.
  В этой поставке таких снимков нет: схемы в `docs/images` рисуют путь, но не заменяют
  проверку на конкретной версии кабинета.
- **Даты и версии.** Версия моста в примерах — `0.1.0`. Версия образа Runtime — тег,
  который вы собрали или получили; фиксируйте его в акте приёмки.

## 7. Что проверено, а что требует решения

**Проверено по коду и скриптам на 28.10.2026:**

- установщик Runtime: флаги, генерация `BC_RUNTIME_ADMIN_TOKEN`, запись
  `infra/runtime.env` с правами `600`, вызов bootstrap;
- bootstrap: создание tenant/workspace/owner, выдача первого токена один раз, проверка
  `/actuator/health/readiness`, вывод `API URL`;
- лицензия: HMAC-токен, привязка к `instance-id`, бессрочный ключ без `expiresAt`,
  состояния `LICENSE_ACTIVE`, `LICENSE_GRACE`, `LICENSE_READ_ONLY`, `LICENSE_REVOKED`,
  `LICENSE_MISSING`;
- страница `/runtime-admin/` и `POST /api/v1/runtime/license`: установка ключа без
  перезапуска, запись в `/app/data/license.key`, предупреждения оператору;
- Runtime admin API: `POST /api/v1/runtime/bootstrap`, `POST /api/v1/runtime/tokens`,
  `POST /api/v1/runtime/tokens/{id}/revoke`, `GET /api/v1/runtime/status`;
- токены Copilot: `GET/POST /api/v1/api-tokens`, `POST /api/v1/api-tokens/{id}/revoke`,
  scopes, лимит 20 активных токенов, 60 запросов в минуту;
- ingest: `POST /api/v1/documents:ingest`, обязательный `Idempotency-Key`, SHA-256,
  коды 201/200/400/409;
- ELSTER: `GET /api/v1/exports/elster?year=&format=json|csv`, колонки CSV;
- мост: CLI `init`, `import`, `test`, `doctor`, `status`, `run`, пути `/data/...`,
  переменная `BRIDGE_TOKEN`.

**Требует решения или живой проверки:**

1. Точные имена архивов моста и ссылка на скачивание — их выдаёт Firmspace вместе с
   поставкой; публичного реестра образов нет.
2. Дистанционная проверка отзыва: код читает `LICENSE_CHECK_URL` и опрашивает кабинет
   каждые 6 часов, но текущий compose-файл не передаёт эту переменную в контейнер.
   Проверьте `printenv LICENSE_CHECK_URL`; без неё отзыв из кабинета не доходит.
3. Коммерческие условия лицензии (срок, план, цена) — решение договора. Для бессрочной
   лицензии в ключе **нет** `expiresAt`; срочная лицензия содержит дату.
4. Контакты поддержки, часы и SLA в этой поставке не заданы — фиксируются в договоре.
5. Сквозной production-прогон каждой модели на стенде клиента — до приёмки.
