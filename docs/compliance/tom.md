# Technische und organisatorische Maßnahmen (Art. 32 DSGVO)

Что реально реализовано и где проверено; то, что зависит от оператора, помечено «оператор».

| Область | Мера | Проверка |
|---|---|---|
| Конфиденциальность — доступ | Вход по паролю с политикой; блокировка после ошибок; необязательный второй фактор; сессии на сервере, cookie HttpOnly/Secure | `AuthFlowIT`, `MfaLoginIT` |
| Конфиденциальность — права | Роли и права (RBAC), права на каждом маршруте | `UiContractIT`, тесты авторизации |
| Конфиденциальность — разделение | Каждое пространство — отдельный арендатор; политика строк в БД (RLS ENABLE+FORCE); тест изоляции для каждой новой таблицы | `TenantIsolationSuiteIT`, `SearchIsolationIT` |
| Конфиденциальность — хранение | Документы шифруются AES-256-GCM, ключ пространства защищён ключом платформы | `EncryptingBlobStoreTest` |
| Передача | Только HTTPS; HSTS и CSP на прокси; внешний ИИ выключен по умолчанию | `infra/nginx` |
| Целостность | Журнал изменений (кто, когда, что); журнал доступа к документам; хеши содержимого | audit-тесты |
| Вредоносные файлы | Проверка загрузок: тип по содержимому, архивы, антивирус ClamAV | `FileSecurityScannerTest` |
| Доступность | Резервное копирование и процедура восстановления (скрипты); проверки здоровья | `infra/scripts`, `docs/runbook.md`; **оператор**: график и проверка восстановления |
| Устойчивость к злоупотреблению | Ограничение частоты запросов; отдельные лимиты входа и приёма почты | `RateLimitIT` |
| Разделение целей | Данные пространств не смешиваются; ИИ не принимает решений с правовым эффектом; серьёзность риска считается правилами | дизайн, `docs/security.md` |
| Проверка и оценка | Автотесты изоляции и прав при каждом изменении; сканирование зависимостей и образов в CI | `.github/workflows/ci.yml` |
| Организационные | **оператор**: обязательство о конфиденциальности, обучение, управление доступом сотрудников, процесс утечки (`breach-plan.md`), договоры по Art. 28 |
