# Безопасность и изоляция tenant для новых модулей

Источник требований: `docs/task.md` §3, §4, §21; `docs/MASTER_SPEC_BUSINESS_MEMORY_RADAR.md` §13.2, §15.

## Существует

- Изоляция: `tenant_id` в каждой бизнес-таблице, RLS `ENABLE`+`FORCE` (`V13__row_level_security.sql`), набор `TenantIsolationSuiteIT`, контекст `RequestContext` (из сессии, не из тела запроса).
- Права: каталог `permissions`/`roles`/`role_permissions` (V12); проверка `@PreAuthorize` на контроллерах; доступ к делам, временный доступ, правило личных документов семьи.
- Политики доступа: подписка (`SubscriptionAccessPolicy`), тариф и кабинет (`billing/PlanFeatures` для путей `/api/v1/invoices`, `/contracts`, `/mail` и др.).
- AI: allowlist инструментов, права пользователя, подтверждение рисковых действий (`ToolPolicy`).
- Аудит: `audit_events` (append-only триггер).

## Правила для каждой новой задачи BM/RD/CA

1. Права — миграцией **до** кода (R-04), затем `@PreAuthorize`.
2. Миграция новой таблицы: `tenant_id NOT NULL`, RLS `ENABLE`+`FORCE`, политика, индекс по tenant.
3. Тест: данные другого tenant недоступны (чтение, список, поиск, AI-выборка).
4. Фоновая оценка исполняется в контексте tenant (`RequestContext.runAs`).
5. Значимые действия пишутся в аудит с `correlation_id`; для согласований — со ссылкой на согласование и хеш содержимого (D-09).
6. Секреты и содержимое документов не попадают в логи.

## Новые права (R-04, предложение)

| Право | Назначение |
|---|---|
| `memory.view` | видеть связи, факты, хронологию |
| `memory.confirm` / `memory.reject` | подтвердить/отклонить связь или факт |
| `radar.view` | видеть находки |
| `radar.triage` | подтверждать, отклонять, откладывать, назначать |
| `radar.manage_rules` | менять чувствительность и правила |
| `autopilot.plan` | создавать и менять план дела |
| `autopilot.execute` | исполнять шаги, подготовленные к исполнению |
| `approvals.decide` | принимать решения по согласованиям |

Назначение ролям — по существующей матрице V12 (OWNER, ADMIN — все; MANAGER — всё, кроме `radar.manage_rules`; EMPLOYEE — `memory.view`, `radar.view`; прочие — по запросу владельца). **Это предложение, не решение владельца.**
