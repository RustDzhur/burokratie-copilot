# Архитектурные диаграммы

Формат — Mermaid (отображается в GitHub и в просмотрщиках Markdown). Условные обозначения во всех диаграммах:

- **сплошная рамка, светлая заливка** — существует в коде на дату аудита (2026-10-14, коммит `c44230b`);
- **пунктирная рамка, жёлтая заливка, пометка «план»** — планируется (задачи `docs/implementation-plan.md`), в коде нет.

| Файл | Что показывает |
|---|---|
| [`01-modules.md`](01-modules.md) | общая схема модулей |
| [`02-data-flow.md`](02-data-flow.md) | потоки данных: приём → обработка → действия |
| [`03-er-core.md`](03-er-core.md) | ER-диаграмма основных существующих сущностей и планируемых добавок |
| [`04-business-memory.md`](04-business-memory.md) | Business Memory: что из чего строится |
| [`05-radar-engine.md`](05-radar-engine.md) | движок Radar и жизненный цикл находки |
| [`06-case-lifecycle.md`](06-case-lifecycle.md) | жизненный цикл дела (статусы канонические, D-03) |
| [`07-approval-flow.md`](07-approval-flow.md) | подтверждение действия с привязкой к содержимому (D-09) |
| [`08-document-lifecycle.md`](08-document-lifecycle.md) | путь документа от получения до завершения дела |

Диаграммы не заменяют код и не изображают желаемое как существующее: любой элемент без пометки «план» можно найти в репозитории по имени.
