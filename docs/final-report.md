### Что аудит не видел и что нашли проверки

* Второй фактор **не требовался при входе**: TOTP можно было подключить, но сессия выдавалась как раньше.
  Теперь сессия с подтверждённым фактором доступна только для проверки кода и выхода (`MfaLoginIT`).
* Задачу, созданную из интерфейса, **нельзя было завершить** (бэкенд требует критерий завершения, форма его не
  спрашивала). Форма теперь спрашивает, в списке есть действия «Начать / Блокировать / Завершить».
* Экран `/notifications` был в навигации и на карточке дашборда, но **страницы не было** (404). Добавлена,
  вместе со счётчиком непрочитанных в верхней панели и тестом «каждый экран реестра имеет страницу».
* Серверные страницы (`not-found`, лендинг) падали при рендере из-за вызова клиентской функции; ни сборка,
  ни линт, ни тесты этого не ловили. Добавлен тест на границу `'use client'`.
* Пустой экран в состоянии «401»: нигде не был подключён переход на вход. Теперь любой 401 ведёт на `/login?next=…`
  (путь проверяется, внешние адреса не принимаются).
* Реальные дефекты бэкенда, найденные `UiContractIT`: `template_fields.source_path NOT NULL` ломал создание
  шаблона; `citext` уходил клиенту объектом; JSON имён шаблонов собирался вручную; неизвестное слово enum давало
  500 вместо 400; ссылка проверки почты не имела повторной отправки.

## 3. Что НЕ проверено

1. **`pnpm build` до конца** не дожидался: шаг «build traces» зависает, пока репозиторий лежит в синхронизируемом
   iCloud-каталоге (аудит, M3). Компиляция, проверка типов и генерация 36 страниц проходят. Рекомендация —
   держать репозиторий вне `~/Documents`. `.next/standalone/server.js` в этом окружении **не подтверждён**.
2. **Docker-образы не собирались** (ни api с tesseract/clamav, ни web).
3. **Автоматических браузерных тестов нет.** Ручной проход выполнен, но не воспроизводим в CI.
4. **MFA:** принуждения «MFA обязателен для аккаунта» при входе нет — если владелец потребовал MFA, а у
   пользователя фактора ещё нет, он войдёт и увидит это только в настройках безопасности.
5. **Уведомления:** тексты строятся из ключей (`titleKey`), каталога сообщений для них нет — экран показывает
   читаемую форму ключа. Источников уведомлений в коде почти нет (создаёт только тест/сервис).
6. **Срок хранения архива** не вычисляется: экран честно показывает «неизвестно», пока не применена
   подтверждённая политика хранения (ТЗ запрещает придумывать сроки).
7. Скан «на устройстве»: задание ставится в очередь, **забирает его агент устройства** (его здесь нет).
8. Качество переводов de/en/ru, юридические формулировки, нагрузка на рабочем пути с токеном — не проверялись.

## 5. Как запустить и увидеть, что работает

```bash
JAVA_HOME=$(/usr/libexec/java_home -v 21) services/api/mvnw -f services/api/pom.xml clean verify
cd apps/web && pnpm install && pnpm test && pnpm typecheck && pnpm lint
scripts/facts.sh --tests
scripts/check-doc-references.sh
```

Локальный стек: API (`java -jar services/api/target/burokratie-copilot-api.jar --spring.profiles.active=dev`,
порт 8080 или `--server.port`), затем `cd apps/web && BC_API_ORIGIN=http://localhost:8080 pnpm dev`.
