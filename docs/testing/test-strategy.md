## Известные ограничения прогонов

- Полный прогон бэкенда в среде аудита даёт ошибки исчерпания соединений БД (`IdempotencyIT`, `SchemaIT`, `FlywayMigrationIT`); эти классы проходят при отдельном запуске (HD-TEST-01).
- Ручная проверка клавиатуры и screen reader не выполнена (`docs/accessibility-checklist.md`): нужен человек.

## Правила для новых модулей (BM, RD, CA, TR, SM)

1. **Позитивный и негативный тест на каждое правило Radar.** Негативный — случай, где правило не должно срабатывать.
2. **Тест изоляции tenant на каждую новую таблицу и каждый новый эндпоинт** (чтение, список, поиск, AI-выборка).
3. **Идемпотентность**: повторная оценка/доставка не создаёт дубль (параллельный запуск — отдельным тестом).
4. **Права**: отказ без права и разрешение с правом.
5. **Синтетические данные**; реальные письма и внешние отправки в тестах запрещены (тестовый провайдер).
6. **UI**: состояния loading/empty/error/forbidden, клавиатура, axe; каждая кнопка вызывает API (проверяет `contract.test.ts`).
7. Статус `IMPLEMENTED_AND_TESTED` в матрице ставится только при наличии теста именно на заявленное поведение.

## Оценка качества AI (RD-09, ПЛАНИРУЕТСЯ)

Набор: `services/api/src/test/resources/eval/` — синтетические документы по категориям: корректные счета, дубликаты, изменённые суммы, разные даты, ошибочный OCR, отсутствующие страницы, противоречивые условия, неизвестные контрагенты, неоднозначные письма, prompt injection, недостаточные доказательства, ложные совпадения. Для каждой категории — ожидаемый результат.

Метрики: precision, recall, false positive rate, доля ответов с корректными источниками, доля отказов от неподтверждённых выводов, число повторных предупреждений, качество восстановления после ошибок.

**Пороговые значения не заданы** и будут записаны сюда только после базовых измерений; до тех пор пороги классификации (`classification.auto_accept_threshold`, `matching.auto_link_threshold`) считаются предварительными.
